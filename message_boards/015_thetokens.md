> ### Claude OAuth Token Lifecycle
>
> The fuel gauge uses Anthropic's OAuth system (same as Claude Code CLI) to get
> real-time usage data. Here's how it works:
>
> **Token chain:**
> - **Refresh token** (`sk-ant-ort01-*`): Stored in Coolify as `CLAUDE_REFRESH_TOKEN`.
>   Valid ~20 days. Used to auto-mint fresh access tokens.
> - **Access token** (`sk-ant-oat01-*`): Auto-generated by the proxy every ~8 hours
>   via `POST platform.claude.com/v1/oauth/token`. Cached in-memory, auto-renewed
>   5 minutes before expiry. Never needs manual intervention.
>
> **What happens when tokens expire:**
> | Token | Lifespan | What happens | User action |
> |---|---|---|---|
> | Access token | ~8 hours | Auto-refreshed by proxy using refresh token | None — fully automatic |
> | Refresh token | ~20 days | Fuel gauge shows amber warning: "Token refresh failed" | Run `claude` locally once (it re-auths), then update `CLAUDE_REFRESH_TOKEN` in Coolify |
>
> **How to update the refresh token** (every ~20 days):
> ```bash
> # 1. Run any claude command to trigger re-authentication
> claude --version
> # 2. Extract fresh refresh token from macOS Keychain
> security find-generic-password -s "Claude Code-credentials" -a "thomasthemaker" -w \
>   | python3 -c "import sys,json; print(json.loads(sys.stdin.read())['claudeAiOauth']['refreshToken'])"
> # 3. Update in Coolify: Settings → Environment Variables → CLAUDE_REFRESH_TOKEN
> ```
>
> **Credential priority order in the proxy:**
> 1. `CLAUDE_REFRESH_TOKEN` → auto-mints fresh access tokens (recommended)
> 2. `CLAUDE_OAUTH_TOKEN` → static access token, expires ~8h (fallback)
> 3. `CLAUDE_AUTH_JSON` → legacy format
> 4. `~/.claude/` credential files on host
>
> **Error visibility (no silent failures):**
> - Token expired → `"⛽ Claude OAuth token EXPIRED — run claude auth login"`
> - API failed → `"⛽ Claude usage API failed: <specific error>"`
> - API key used → `"API keys cannot check subscription quota"`
> - No token → Provider omitted from panel entirely (503)
